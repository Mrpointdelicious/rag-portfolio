## 事实复核与隔离

`review_policy.json` 规定统一事实等价标准，`review_audit.json` 记录全部 42 组旧事实的复核结果，包括未增加替代的理由。9 组新增完整等价表述；外骨骼目的组同时收紧为训练与矫形用途均须支持。年龄、疾病、主要结局、否定和年份不能省略。证据绑定同一原始 PDF 的规范化页文本、页码、字符范围及哈希；隔离页不参与检索或扩展。

Gold 复核由同一代理完成，旧结果此前已暴露，属于技术原文核对，没有独立临床审批。新题来自同一语料，部分事实也在旧题出现，不能视为外部独立验证。报告单列旧排名在新旧 Gold 下的差异，避免把标注修订当作检索收益。

语料和旧向量只读复用；向量缓存通过模型 revision、维度、输入指纹验证后复制到 `.local/medical_rehab_v3/`。v3 的查询缓存、真实重排缓存、Qdrant 集合及点 payload、开发选择和结果均使用独立实验标识。禁止混入元宇宙领域或其他医学版本的索引 payload。

## 七组对照

| 方式 | 行为 |
| --- | --- |
| hybrid | Dense Top-20、BM25 Top-20、RRF k=60 |
| reranked_hybrid | 基础混合候选经真实 qwen3.7-text-rerank 重排 |
| v2_source_routed_rerank | 旧版去标题、分来源召回与轮流取块的组合基线 |
| preserved_query | 保留完整问题及文献标题语义，合并全局与明确来源召回后重排 |
| decomposed | 在前一组基础上增加来源×问题维度的中英子查询，最多 6 个任务，候选池最多 80 块 |
| coverage | 在相同子查询候选池上，结合真实重排分数与子查询排名的边际覆盖选择前缀 |
| context_expanded | 与 coverage 排名相同，只比较相邻原文扩展后的上下文包 |

规划器只接收用户问题、标题别名和文献元数据。来源必须由问题明确指向；疾病、设备和文献主题保留在查询中。维度来自固定中英规则，不读取题号、Gold、参考答案或候选来源提示。选择器保留真实重排分数，另外记录覆盖目标及选择过程。

全部方式同时报告固定 Top-5 和统一长度预算指标。上下文包最多接纳 8 个种子块，正文及渲染元数据合计不超过 **4000 个 cl100k_base 参考 token**。该 tokenizer 用于公平比较，不是 Qwen 计费 tokenizer，不能据此估算账单。扩展最多取同页两侧各 240 字符，尽量落在句子边界；相交区间合并。只使用冻结页文本，不生成摘要，也不借用其他页或隔离页。

完整覆盖要求问题的所有事实组都有支持。相邻证据可联合覆盖同来源、同页的连续事实区间；跨页、跨来源或有缺口的区间不能拼成完整支持。候选覆盖、Top-5 覆盖及预算内覆盖分别保存，便于区分召回、排序和打包问题。

52 道开发题的前三组基线从 v2 的真实运行记录重放，并以 v3 Gold 重算；新方案真实调用模型服务。20 道新保留题的各组基线与新方案均实时运行。重放记录不用于比较请求延迟。

## 运行与结果核验

在具备本地 PDF、冻结语料、v2 真实报告及已配置模型服务的环境中，首次运行顺序如下：

```powershell
uv sync --locked --extra medical
.venv/Scripts/python.exe tools/eval_medical_v3.py --freeze
.venv/Scripts/python.exe tools/eval_experiment.py medical_rehab_v3 --split dev
.venv/Scripts/python.exe tools/eval_experiment.py medical_rehab_v3 --split test --open-sealed-test
.venv/Scripts/python.exe tools/report_medical_v3.py
```

当前检出已完成开发选择和保留题，开发和测试运行步骤会拒绝重复调参或再次打开已完成测试；`--freeze` 只允许相同 Gold 的幂等校验。开发选择依次比较预算内完整覆盖、Top-5 完整覆盖、预算内事实覆盖、MRR 和固定方式顺序，选择 `context_expanded`。测试必须匹配选择记录、题集封条、Gold、模型和实现/配置指纹。

报告工具重建问题规划、选择次序、原文映射、上下文包及 token 计数，并重算逐题和聚合指标后，才发布 `artifacts/eval/medical_rehab_v3/summary.json`。全文证据卡、上下文包、模型请求记录和缓存留在 `.local/medical_rehab_v3/`，不进入公开代码包。

## 输入边界

患者实测值、当前训练记录、个体适应证和实时业务状态单独走输入检查，缺失时要求相应数据；可回答的文献范围问题仍检索文献，同时保留患者输入限制。本轮验证的是确定性输入路由，未训练或评估生成式拒答、临床回答或患者数值计算。患者数据来源现状见[核查记录](../../docs/patient-measurement-data-audit.md)。
