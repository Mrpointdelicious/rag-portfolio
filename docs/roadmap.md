# 求职作品开发路线

定位：展示通用 RAG 系统的完整工程链路。默认演示素材为自编项目文档、技术 FAQ 和有使用许可的公开资料；先固定一套小型可重复的语料，再扩展规模。

| 阶段 | 主要交付 | 验收与展示产物 |
|---|---|---|
| P0 独立基线 | 从 MetaKnowledgeBase M1 复制，独立包名、Git、凭据、端口和数据卷 | 本仓库测试及 smoke；可复现启动说明 |
| P1 通用内容治理 | 新迁移引入通用 KB/受众；文档上传、解析、版本、hash、切分、人工审核 | 一份 Markdown/TXT 文档可追溯到版本和分块；并发编辑与重复导入测试 |
| P2 检索与发布 | 模型适配、dense/sparse、RRF、重排；完整索引构建、激活、撤销、回滚；任务续租 | 可定位引用的检索；失败不影响当前发布；撤销后不可见 |
| P3 引用问答与演示 | LLM 适配、基于证据的回答、无证据处理；文档/任务/问答界面 | 一段可重复的端到端演示，引用可以回到原文 |
| P4 评测与工程验证 | 固定问题集、gold evidence、消融实验、故障注入、恢复及监控 | 检索质量、引用正确性、延迟与成本报告；运行手册 |
| P5 作品整理 | 架构图、设计取舍、实验结果、演示视频/截图、项目经历说明 | README 与简历条目都能对应实际实现、测试或测量记录 |

当前 P0 已验证。P1 的文档、版本、审核和 Markdown/TXT 分块服务层代码已准备，见 [调用约定](document-flow.md)；按本轮要求未运行测试。P1 的通用模型迁移、HTTP 上传和长任务尚未实现，P2–P5 待开发。不使用来源项目的医疗资料数量、临床质量目标或内部系统联调记录作为本项目成果。

## 下一轮任务

1. 明确通用知识库 code、audience 和 metadata，新增 `0002` 迁移并同步 API/模型/测试。已有医疗与场景字段是否保留为可选扩展，写入设计决策。
2. 实现文档与版本服务，正文/元数据 hash、草稿乐观锁、提交冻结和审核审计。
3. 支持小型 Markdown/TXT 样本导入，保存来源和切分配置；PDF/DOCX 后续扩展。
4. 首个长导入任务前实现租约续期、每批写入的租约核验、进度和断点恢复。
5. 同步建立问题集，包括有答案、无答案、权限、更新、撤销和冲突问题。

## 评测与展示约定

- 同一语料、问题集、模型 revision 和资源配置下对比实验，记录 corpus/config hash。
- 检索评估可采用 Recall@k、MRR/nDCG；回答评估记录引用正确性、证据支持度和未知问题处理。阈值在首轮基准后设定，不预填实验收益。
- 每阶段交付可执行命令、演示输入、预期输出与失败样例。
- 项目经历区分“继承基础”“本人新增设计与实现”“实测结果”，便于面试时准确说明贡献。
- Dify 导入与场景导航不作为通用作品首轮必需功能，可在核心 RAG 链路完成后选择扩展。
