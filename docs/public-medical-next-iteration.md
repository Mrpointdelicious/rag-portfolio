# 下一步迭代方向：完整知识库服务化与业务评测

日期：2026-10-12。用户批准后，第1/2项已完成隔离候选实现和真实业务基线；第3/4项采集了证据，尚未据此修复或优化。执行结果见[业务基线与验收](medical-business-v1-results.md)，以下保留本轮规划依据。12道已知问题继续暂缓定点修复。

## 决策依据

现有公开7篇已完成真实Dense/Hybrid/Reranker和6个MetaAgent隔离案例；合并14篇仅运行本地BM25的来源/版次冒烟检查，尚无完整合并库的实时Hybrid或Agent业务基线。用户已确认另外7篇旧资源可用、第三方内容已排除，同作品取最新版本，D042为2023版/2024年发表。这为下一轮按确认的使用范围建立合并库候选提供了输入，但不会追改历史许可字段或扩大公开发布范围。

首轮50题多数带NEWxx/Dxxx来源代号，主要衡量已指定文献中的证据定位。MetaAgent实际面对的是用户解释训练记录、核对医嘱、理解量表、查找知识和操作帮助等问题，用户通常不会知道文献代号。当前证据还不足以判断这类业务任务的整体完成情况。

此外，已有业务候选已经处理过字段缺失、计划与实际结果、能力限制和失效引用；这些能力应复用。真实医学案例仍暴露了“范围拦截”被转述成“没有检索命中”的问题，说明最终回答需要保留服务状态。这是下一阶段需要评测的接口语义，不在本轮修复。

依据：[医学真实评测](public-medical-corpus-v1-eval.md)、[医学服务设计](public-medical-corpus-v1-design.md)、[MetaAgent契约业务评测](../../metaAgent/docs/contract-business-eval-results.md)。

## 建议优先顺序

| 顺序 | 方向 | 最小交付 | 验收方式 |
|---|---|---|---|
| 1 | 完整知识库形成可验证候选发布 | 在已确认范围内建立14篇合并库独立索引，复用现有retrieval-v1；补齐候选加载、版本校验、撤销与回滚的最小流程 | 新query实际调用Embedding/重排；语料与索引绑定；回滚后返回旧版本来源；原公开7篇与合并库分别报告 |
| 2 | 用实际业务问法建立新基线 | 自然中文问题不提供内部文献代号；覆盖找资料、解释、比较、追问和证据不足 | 先冻结输入与评分，再测现有方案；同时记录证据返回、模型可见和最终回答是否完成任务 |
| 3 | 明确回答依据与缺口 | 复用Evidence/FactView；区分患者记录、文献结论与解释；保留无命中、范围限制、超时等状态 | 关键结论可定位来源；文献群体结果不变成患者实测；服务失败不被转述为无知识 |
| 4 | 衡量真实运行代价 | 记录查询数、模型调用数、预算、耗时、失败与恢复轨迹 | 同条件比较；记录p50/p95及失败率；确认存在可量化浪费后再决定缓存或算法变化 |

第一轮建议只把第1项与第2项做成一个可审阅闭环；第3/4项先在评测中采集证据，再按结果确定实现优先级。继续复用单Agent与现有协议。

版本治理需要区分作品、资源和发布版本。以DOI/题名/作者等核对同作品，依据出版或修订记录判断新旧，保留被替代资源的关联；不能用文件hash不同推断新版本。D042的版次2023与发表年2024分字段保存。新版本未完成候选验证前，不自动替换当前有效发布。

## 下一轮业务EVAL建议

初始规模建议40个新条件，分8类，每类3个开发、2个新保留，共24开发/16保留。数量可在编题复核时调整，冻结后不得为分数删题。它们必须是新问题及新判断条件，不能只删除旧题中的NEWxx当作独立新测试。

| 业务类别 | 例子或关注点 |
|---|---|
| 自然语言发现来源 | 不给文献ID，询问卒中步态训练相关研究，能否找到适用资料并说明来源 |
| 量表与记录解释 | 解释量表含义与已提供的实测值；没有实测时不能由论文补值 |
| 研究适用条件 | 人群、病程、干预与结局是否适用；不把不同疾病或结局的研究混用 |
| 多来源比较 | 两项研究结论不同，分别说明研究条件、结论与不能合并的部分 |
| 版本与冲突 | 问指定版次、现行候选版次或历史版本；区分版次和发表年 |
| 多轮追问 | “刚才那项研究”“这个数字”等指代、证据过期、上下文切换 |
| 知识不足及服务状态 | 无资料、部分覆盖、范围拦截、超时分别解释；仍回答已支持部分 |
| 操作帮助与医学知识路由 | 软件功能问题与康复知识问题分开查；已有信息足够时完成回答 |

患者记录相关条件使用独立契约合成夹具，避免真实患者数据成为编题前提。当前医学远程服务只验收operator隔离路径；新的患者远程场景需要单列能力与作用域实现，不能把合成身份当作理由绕过现有门控。操作帮助也须指定实际批准资料；暂缺资料的类别明确标为未测试。

评分至少分开：必要证据覆盖、回答任务完成、关键陈述支持/引用、不可回答原因、可回答却拒绝、版本/范围正确性，以及调用数和耗时。结构检查只能确认字段和引用成员；陈述是否由原文支持需要独立复核。首轮先给基线，不预设性能提升数字，不合并成一个总准确率。

## 固定回归如何参加下一轮

1. 原50题按既有语料、锚点和4000 cl100k预算独立重跑，报告为已打开题集回归；12题子集逐题单列。集合见 [regression_backlog.json](../eval/public_medical_corpus_v1/regression_backlog.json)。
2. 已新增显式回归入口 `tools/eval_medical_business.py regressions`，复用现有评分读取固定清单，完成50题与12题子集实跑。漏题/运行失败报告为未完成；已知不通过保留基线与当前值，不能用删除题目或全部拒答制造改善。
3. 全部12题状态暂为 `deferred_known_failure`。不是要求下一轮先修到12/12；任务是持续测量。以后即使改善，题目仍留在回归集合并追加记录。
4. 新合并库与原公开库的source/segment命名空间不同。要在新库测试相同问题，必须新建并复核证据映射、登记新版本；原精确位置评分不能直接套用。新库成绩与旧公开库成绩分开。
5. 旧业务C/B/E场景按其原协议单独回归，防止患者事实、能力限制与引用保护退化；分母不能与医学12题相加。
6. 新16题保留集在开发选型后只评一次。历史heldout及本次12题都已打开，不能代替它。

## 下一轮完成标准

交付一个可以明确回答“使用哪一版知识、取到了哪些证据、支持哪些结论、为什么未完成”的合并库候选服务与端到端业务基线，附版本回滚记录、新业务分项结果和固定回归报告。没有完整14篇真实链路结果时，不宣布合并库Hybrid验收完成；没有独立语义复核时，不宣布完整业务通过。

是否继续扩大语料、变更模型、引入GraphRAG或复杂查询规划，应由这轮的新业务缺口决定，暂不列为优先实施项。
